# script.json 模板与写作规范

## 文件格式

`<WORKDIR>/script.json`，一个 JSON 数组，按顺序即分镜顺序：

```json
[
 {
  "idx": 1,
  "kicker": "钩子",
  "caption": "画面上的大字，≤14 字",
  "asset": "assets/01_shot.png",
  "text": "口播文案，TTS 朗读的内容，数字写中文。"
 }
]
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `idx` | ✅ | 从 1 连续编号，决定顺序；文件名 sNN 由它生成 |
| `caption` | ✅ | 画面底部大字，**≤ 14 字**，换行最多 2 行 |
| `text` | ✅ | 口播文案，数字用中文 |
| `asset` | ⬜ | 相对 `<WORKDIR>` 的素材路径（也接受绝对路径）；**留 null 则渲染成纯 CTA 屏**（只有文案没有图，适合结尾） |
| `asset_start` | ⬜ | 仅视频素材用：从第几秒开始截取（如录屏里"AI 开始执行"的片段在第 38 秒 → `38`）。同一段录屏可以按不同起点喂给多个场景 |
| `kicker` | ⬜ | caption 上方的小标签（"原理""内存分层""硬件跨度"…），帮助观众建立信息层次 |

## 字数预算表（火山 1.2x 语速，≈4.2 字/秒，lead=tail=0.35s）

| 目标时长 | 场景数 | 停顿开销 | 配音预算 | 全文目标字数 | 每段字数 |
|---|---|---|---|---|---|
| 45 s | 6 | 4.2 s | 40.8 s | ~171 | ~28 |
| 60 s | 7 | 4.9 s | 55.1 s | ~231 | ~33 |
| 75 s | 8 | 5.6 s | 69.4 s | ~291 | ~36 |
| 90 s | 9 | 6.3 s | 83.7 s | ~351 | ~39 |

**先按表写 → 生成 → 看实测总时长 → 微调**，比一次追求精确高效（有缓存，改动段几秒重生成）。

## 六段叙事公式（1 分钟版）

| 段 | 目的 | 可用钩子写法 | 时长 |
|---|---|---|---|
| 1 钩子 | 留住人 | 痛点反驳「你还在手动干这个？」/ 反常识「这项目才 200 Star，但比收费的好用」/ 结果前置「一句话生成整条视频」 | 6~8 s |
| 2 亮相 | 它是谁 | 一句话定位 = 品类 + 最大特征 | 7~9 s |
| 3 原理 | 凭什么 | 只讲**一个**最核心机制，讲透 | 8~10 s |
| 4 卖点 | 怎么用 | 具体数字 / 对比，配画面上的图 | 8~10 s |
| 5 亮点 | 最抓眼 | 挑视觉上最有冲击力的功能 | 7~9 s |
| 6 引导 | 去哪找 | 协议 + 项目名 + Star 数 | 6~8 s |

## 素材分配原则

- **GIF 给"亮点"或"原理"段** —— 动起来最能留人
- **视频录屏给"亮点"段** —— 动态素材里优先级最高，比 GIF 更清晰；先用 `-ss` 抽帧看清每个时间点在演示什么，再用 `asset_start` 把最有戏的几秒分给不同场景
- **dashboard/界面截图给"钩子"和"亮相"** —— 最直观
- **benchmark/架构图给"原理"和"卖点"** —— 配合讲数字
- **`og.png` 卡片给"亮相"** —— 它是项目的正式门面
- **结尾用 `asset: null` 的纯 CTA 屏** —— 视觉上收得住
- 一张图只用一个场景；素材多于场景数时，把最像的那几张留到下一条视频

## 写作注意

1. **数字一律中文**：「百分之八十九」「三万三千」「十一 G」「二十五 G」，TTS 读阿拉伯数字容易出错
2. **英文专名保留**：项目名（Colibri）、模型名（GLM、DeepSeek V4）、技术词（token、RTX 5090）保持原样，火山 TTS 中英混读没问题
3. **OCR 读不准的数字别写进文案**，交给画面自己呈现（写错比不写伤害大）
4. **不用绝对化表述**：最好/第一/唯一/绝对 —— 广告法风险，且已被用滥反而降低可信度
5. **别复述界面**：不要写"左上角有个按钮"这种话，观众自己能看见；文案要讲画面**讲不出来**的东西（为什么、意味着什么）
6. **数据标时点**：Star 数和版本天天变，口播或字幕里带上"截至 X 年 X 月"

# cover.json 模板（封面文案）

`<WORKDIR>/cover.json`，可选。**封面文案要单独写，不要把 caption 搬过来**——caption 是"配着画面说的话"，
封面是"在信息流里骗人点进来的那句话"。缺这个文件时会自动用第 1 场 caption 兜底，能出图但不够标题党。

```json
{
  "badge": "开源精选",
  "headline": "一个 **10MB** 的软件\n替掉七款工具",
  "sub": "SSH · RDP · 数据库 · 容器 · 内置 AI Agent",
  "cta": "GitHub 搜 uniterm",
  "asset": "assets/demo.mp4",
  "asset_start": 53,
  "callouts": [{"text": "AI 自主执行", "x": 0.70, "y": 0.15}]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `headline` | ✅ | 封面大字；`\n` 强制换行，最多 2 行；`**...**` 出琥珀色高亮 |
| `sub` | ⬜ | 副标题一行，≤ 22 个全角宽度 |
| `badge` | ⬜ | 左上角徽标，默认「开源精选」 |
| `cta` | ⬜ | 行动胶囊，默认「GitHub 搜 <name>」，动词开头最有效 |
| `asset` `asset_start` | ⬜ | 封面主体素材（可与正片不同，挑信息密度最高的那一帧） |
| `callouts` | ⬜ | 圈重点标签：`x`/`y` 是相对卡片的 0~1 比例，**`y` 取 ≥ 0.15**，否则压住窗口标题栏 |
| `accent` | ⬜ | 强调色，如 `[46,160,67]`，默认品牌绿 |
| `title` | ⬜ | 卡片窗口标题栏文字，默认仓库名 |

## 封面文案的硬规则

- **单行 ≤ 6 个全角字符等效宽度**（数字/英文按 0.55 折算，剩下按 1 算）。
  超了这个宽度，脚本会自动压小字号去适配，字一变小就在信息流里失去气势。
  「一个 10MB 的软件」≈ 4 + 0.5 + 2.2 = 6.7 → 两行版式下字号正好 120~130px
- **两行封顶，每行都要有信息**：第一行给"对象"，第二行给"结果/反差"
- **数字必须出现**：`10MB`、`30+`、`七款`、`493 Star` —— 数字是封面里最抓眼的部分
- 不要用绝对化表述（最好/第一/唯一），不要复述界面
